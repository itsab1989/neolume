## 0. How to use this spec with a coding agent

This document is meant to be handed to a developer or an AI coding agent as the implementation brief. Give it the whole file
plus the screenshots in [`screenshots/`](screenshots/) as visual references. The source tree of the 2014 build is the
reference implementation; Part C lists which parts port as-is.

**Suggested milestones (build and verify in this order; the same order as phases 2 – 10 of [PORTING-WITH-AI.md, section 5](PORTING-WITH-AI.md#5-phases-2--10--feature-milestones), phase = milestone + 1):**

| # | Milestone | Requirements | Verify with |
|---|---|---|---|
| 1 | Shell: canvas, design tokens, focus ring, router with back stack, hint bar, toast, dialog, panel | A3, A16 | focus scenes; RETURN chains (A3.4) |
| 2 | Connection: server address + per-profile token (from a setup file **or** on-device plex.tv sign-in), profile picker, PIN | A4, C2 | unit tests for start rules (PROF-2) |
| 3 | Home from cache, then network; rows, hero | A5, A17 | `home` benchmark; screenshot `home.png` |
| 4 | Library grid, sort/filter, A–Z, details (movie, show, season, episode) | A6, A7 | `library.png`, `details.png`, `series.png` |
| 5 | Player: decision, direct play/stream/transcode, tracks, subtitles, seeking, markers, up next, resume, timeline | A9 | player matrix (C3, item 4) |
| 6 | Search; settings (all rows of A14) | A8, A14 | generated settings table = your settings screen |
| 7 | Music and audiobooks; mini player | A10 | `music.png`, `audiobooks.png`, `artist.png` |
| 8 | Discover + watchlist, other servers, screensaver, library background, accent colours, anime rules | A8, A11, A12 | remaining screenshots |
| 9 | Offline and error states, texts in both languages, privacy, accessibility, then a performance pass on the slowest target device | A13, A15, A17, A18, A19 | offline scenes; text length limits; benchmark scenarios, budgets |

**What to test first:** the pure logic – start-route rules (PROF-2), decision query and fallback chain (PLAY-3…PLAY-6),
automatic track choice (PLAY-9), marker/countdown rules (PLAY-17, PLAY-18), seek accumulation (PLAY-22), home-row merge (HOME-4),
library query building (LIB-3). In the reference code these are DOM-free modules with Node unit tests (`tests/*.test.js`);
port the tests together with the logic.

**How to check parity:**

1. Run the reference app's visual scenes on a computer: `npm ci && npm run build`, then
   `FIREFOX=<path to Firefox> node tools/visual.js` renders every scene with synthetic data in headless Firefox into
   `tests/visual/current/<scene>.png`. The public repository has no approved baselines, so the run lists every scene as
   having none ("keine Baseline") and exits with an error – expected; these PNGs are your references. Compare your screens
   against them at the same state – the scene names (`home`, `library-sort`, `player-osd`, `details-show-eps`, …) are a
   checklist of states that must exist. On a bigger canvas compare layout proportions, not pixels.
2. Walk the generated settings table (A14) and the routes table (A2) – every row must exist in the port.
3. Run the RETURN chains (A3.4) and colour-key table (A3.3) on every screen.
4. Run the benchmark scenarios (A17.3) on the target device and meet the budgets (A17.1).
5. Walk a person through the acceptance test plan [TEST-PLAN.md](TEST-PLAN.md) on the target TV – at the end of the port
   and whenever you are unsure mid-way. It has one entry per requirement ID of Part A (steps for a person with a remote, or
   a check for you), a 10-minute smoke test, performance and privacy checks and a results template.

**Sources to read besides this file** (all maintained together with the app): the design tokens `design/tokens.json` and

# Part A – Product

## A1 Purpose and principles

**Purpose.** An unofficial client for **Plex Media Server (PMS)** on TVs. In daily use it talks **only to the user's own
PMS in the home network** (PMS-only), starts fast from its own cache, is fully usable with a D-pad remote (and a pointer
remote where the TV has one), and is safe for families (profiles, kids profiles, PINs). No ads, no tracking, no telemetry.
Deliberately **not** in scope: casting, downloads, Watch Together, live TV/DVR, remote access outside the home network.

| ID | Principle |
|---|---|
| PRIN-1 | **Calm over effect.** Dark, flat background; one accent colour; the artwork is the colour. No decorative animation. |
| PRIN-2 | **Focus is always unambiguous.** Exactly one focused element per screen, always in the accent colour, findable from 3 m in under 1 s. |
| PRIN-3 | **Accent means focus or progress.** The accent colour is used only for focus (ring, fill, frame), progress fills, countdown bar, search cursor, spinner and the small overline above hero/detail titles. Badges, active tabs, toggles and chips stay neutral. |
| PRIN-4 | **One focus language.** Cards: one moving ring + card scaled to 1.08. Buttons, chips, keys, tabs, panel entries: accent fill with dark text. Settings rows: accent frame on a dark surface. |
| PRIN-5 | **Predictable navigation.** RETURN always goes back exactly one level (A3.4); every row remembers its column; after every action the focus target is defined (A3.5). |
| PRIN-6 | **Colour keys have fixed meanings** and are always shown in the hint bar; every colour-key function is also reachable with D-pad + OK (A3.3). |
| PRIN-7 | **Performance is design.** No transition is better than a stuttering one. Motion only via transform/opacity on small elements, ≤ 150 ms; no animation while a key is held (A17). |
| PRIN-8 | **Family-safe.** Kids profiles have no account functions, no way into adult profiles without a PIN, friendly texts without jargon (A4). |
| PRIN-9 | **Progressive disclosure.** Short label first; explanation on focus (settings description area), via INFO, or in error dialogs. Technical details (codec, mode) only in INFO panels. |
| PRIN-10 | **Video first.** Over video only compact, nearly opaque islands that appear/disappear without animation. |
| PRIN-11 | **Bilingual without special cases.** No UI text in markup or code; everything comes from string tables, and every text fits its component in every language (A15). |
| PRIN-12 | **PMS-only daily use.** No request to plex.tv in the start path or during normal use, except the optional, clearly separated Discover/watchlist features (A8, A18). |

## A2 Information architecture

Screens ("routes") live on a back stack. Overlays (dialogs, panels, menus, help) stack above the current screen and are
always closed first by RETURN. A collapsible **sidebar** (A3.6) is the main way between top-level screens.

```
start ─┬─> login ──> profiles ──> home ──┬─> details ──> player
       │   (dev build only)      ▲       ├─> library ──> details / album / artist / library (collection, person)
       └─> profiles ─────────────┘       ├─> search / discover ──> details / extdetails / library
                                         ├─> album ──> nowplaying, artist
                                         ├─> settings ──> homerows / railitems / insprows / keys
                                         └─> nowplaying (Green or mini player while audio plays)
```

## A3 Navigation and focus

### A3.1 Input devices

- **NAV-1** The app MUST be fully usable with D-pad (▲▼◀▶), OK, RETURN/Back and the four colour keys. Every function that
  sits on another key (INFO, TOOLS, PLAY, digits …) MUST also be reachable via D-pad + OK (a button, a TOOLS/"⋯" menu entry
  or the hint bar).
- **NAV-2** Pointer remotes (Samsung Smart Control, LG Magic Remote): hover focuses the element under the point, click = OK,
  **long press ≥ 800 ms = TOOLS** for the element under the point, the hint bar is clickable (acts as that key). Pointer
  focus MUST NOT scroll a list under the point – this holds for every list of rows or lines (Home, libraries, Search and
  Discover, detail pages incl. album/artist, DET-9): pointing at a fully visible row focuses it where it is, also the on-screen keyboard and
  "Recent searches" never scroll the results; hit tests use page coordinates (screen y + scroll offset). A partly visible
  row (≥ 40 % visible) or Home's next row is brought in only after the point rests on it **250 ms** (passing over does
  nothing) or on a click – one step, then the pointer is locked until it moves ≥ 40 px and 450 ms have passed. Otherwise
  scrolling happens via edge zones (400 ms dwell, then steps from 400 ms speeding up to 120 ms, or a steady 300 ms when
  "Speed up pointer scrolling" is off; a small arrow pill marks the zone; a click in the zone scrolls one step) or the
  wheel (≥ 150 ms apart). Setting `ptrEdge` ("Pointer scrolls at the edges", default on) switches every scroll-by-resting
  off (edge-zone dwell, partly visible rows, Home's next row); clicks, keys and the wheel still scroll.
  After a key press the pointer is ignored until it moves > 16 px ("last input wins"). **Re-touch** (touchpad remotes send
  no release; putting the finger back makes the point jump to the screen centre): a position within ±8 px of the centre
  that comes after ≥ 1 s without pointer events, or by a jump of more than 200 px, focuses nothing, starts no dwell or
  edge zone and ends a running edge scroll; the next real movement counts normally.
- **NAV-3** Volume and mute always belong to the TV.

| OK | Activate. |
| RETURN | Back one level (A3.4). Overlays first. |

### A3.4 RETURN chains

- **NAV-5** RETURN MUST follow these chains. The sidebar is not part of any chain: it opens only with ◀ (or the pointer),
  and RETURN in the open sidebar only collapses it. A **section** is a screen opened from the sidebar (every library
  including music and audiobooks, Search, Discover, Settings, and any screen an extension adds to the sidebar); once
  RETURN has brought you to the top of a section, the next RETURN follows the per-profile setting **"Back from a
  section"**: "To Home" (default) or "To the previous section" – a history of the sections opened from the sidebar (each
  at most once, most recent first, opening one again moves it to the front; the section you leave drops out; sections no
  longer in the sidebar are skipped; library identity = library id; emptied when Home is opened and on every profile
  switch). The history always ends at Home. Screens below a section (collections, person filters, details, album,
  artist, key guide …) go back exactly one level. *Accept:* from every screen, pressing RETURN repeatedly ends at the exit
  dialog without skipping a level.

| Where | RETURN |
|---|---|
| Overlay open | Closes the topmost overlay (sub-menus step back to their parent menu); focus back to the element that opened it. |
| Sidebar open | Collapses it, focus back to the content (on every screen). |
| Home | (1) focus not on the first card of the first row → jump there · (2) → exit dialog ("Exit {app}?" / "Your place is saved.", focus on Cancel). |
| Library (section) | (1) not in grid row 1 → row 1, same column · (2) → "Back from a section" (Home or previous section). Inside a collection or person filter, or opened from Home's "Show all" card (HOME-14): back. |
| Search / Discover (section) | Results or recent searches → keyboard (last key, query kept) · keyboard → "Back from a section". Search opened with Blue from another screen: keyboard → back to that screen. |
| Details | Back to the calling screen with exactly the old focus. |
| Album / Artist | List/rows → buttons → back. |
| Settings (section) | Row → category → "Back from a section". Key guide and list editors: back to Settings. |
| Player, OSD visible | Cancel a pending seek, else hide the OSD (video keeps playing). |
| Player, OSD hidden | Stop playback (position saved) → calling screen. |
| Now playing | Back; audio keeps playing (mini player). |
| Profiles | At app start: exit dialog · otherwise back. |
| Login, Start | Exit dialog. |

### A3.5 Focus memory and focus after changes

- **NAV-6** Every row remembers its column; every screen on the stack remembers its focus and restores it on return. The
  reference keeps at most 2 screens below the top alive and rebuilds deeper ones from a saved restore state. Whenever a
  screen becomes the top screen again (RETURN, a sidebar entry, also OK on the sidebar entry of the page already open), the
  sidebar is collapsed and the restored focus shows its ring at once – a stale "sidebar open" state must never leave the
  ring invisible.
- **NAV-7** Focus after a state change:
  1. A card disappears (watched in Continue watching, unwatched filter, hide): focus moves to the card that takes its place,
     else the previous one; an emptied row is removed and focus goes to the next (else previous) row. The ring never points
     at nothing.
  2. Back from the player: the calling screen, focused on the **title** that was played (after autoplay: the last played
     episode, with its season tab active).
  3. A background refresh MUST NOT rebuild or reorder the focused row while the user is in it. Its new version waits until
     focus leaves that row (then it is applied at rest), until the screen is entered again, or until **30 s without a key**
     have passed (the screensaver counts as rest; a key starts the 30 s again) – and it is applied **at once** when the
     focused card itself is no longer in the new version (removed from the server; otherwise the user could open a title
     that no longer exists). Then the same card stays focused (same `ratingKey`; if it is gone, the card now at its place)
     at the same screen column where the row allows it; other rows do not move.
     Other rows update in place at rest, keeping their remembered card. Layout changes (rows appearing or disappearing)
     apply on the next visit. A library grid never changes while the user is in it (LIB-10).
  4. Profile switch: focus memory is discarded; Home starts at row 1, card 1.
  5. Dialog/panel closed: focus back on the element that opened it.

### A3.6 Sidebar

- **NAV-8** Collapsed 120 px icon strip, expanded 320 px opaque panel (slides in 150 ms, dims the content). Order: Profile
  (avatar, top) · Search · Discover (optional) · Home · libraries (own server first, then other servers with a second line
  "from {server}") · Settings (bottom). At most **10** entries between Profile and Settings; the rest only via "Customize
  sidebar". Home and Settings cannot be hidden. Opened by ◀ at the left content edge; the current page is marked: the
  section the user is in – details (also album/artist) mark the item's library, wherever they were opened from (until the
  item's library is known the previous mark stays); collection and person views keep their library; a title not on the
  server keeps the mark of the screen it was opened from (Discover, Home, or the library); Home is marked only on Home.
  `librarySectionID` must be taken from the container where the PMS puts it there (C2.1). Collection and person views show the sidebar too. Long entry names wrap to 2 lines in normal
  weight, then "…".
  With the pointer, hovering over the icon strip expands it and a click on an entry works like OK; after such a click the
  sidebar stays collapsed until the pointer has left the icon strip (otherwise the pointer, still resting on the strip,
  would expand it again at once). *Accept:* RIGHT closes and restores the content focus; OK on the current page only
  closes; a pointer click on any entry – a library or Settings alike – leaves the sidebar closed.

### A3.7 Hint bar, toast, dialog, panel

- **NAV-9 Hint bar:** right-aligned at the bottom (y 656–684, on the opaque bottom band), at most **5** entries, colour keys
  drawn as coloured squares with letters A–D, other keys as caps. It shows the hints of the topmost overlay, else of the
  screen. It changes only when the context changes. A hint shows a key only where that key acts on the current focus
  (e.g. no Red "From start" / Green "Audio & subtitles" on the season-tab row of a details page); when the focused item
  changes because its list changed (loaded, added, removed), the hints are recomputed.
- **NAV-14 Hint bar visibility** (setting `hints`, per profile): *Always* (default) · *Briefly* – the bar appears when a
  screen or overlay opens and after Red/Green/Yellow/Blue, INFO or TOOLS, then fades out after ~4 s (opacity only, one
  timer; while hidden it cannot be clicked) · *Off* – never shown, also not the small hint island of the paused player.
  Without a profile (sign-in, profile picker) the bar is always shown. Nothing may be discoverable only through the bar:

## A4 Start, profiles and PINs

### A4.1 Two connection modes

- **PROF-1** *Setup-file mode (release):* a setup program on a computer signs in to plex.tv once and writes `setup.json`
  into the app package (schema C2.4): server identity and LAN addresses, one **server-bound token per profile**, optional
  helper and other servers. The app then talks only to the PMS; plex.tv is never contacted (requests are refused in code).
  Tokens stay in memory and in the package, never in the app's own storage.
  *Development mode (no setup file):* on-device plex.tv PIN sign-in (on the 2014 TV through a LAN TLS proxy, Part B).
  A port to a TV that reaches plex.tv over HTTPS (TLS 1.2) **MUST be built without the helper and without the setup
  program**: it signs in on the device (PIN via plex.tv/link, PROF-10), calls plex.tv directly for Discover, watchlist and
  title details, and keeps tokens in the platform's secure storage. The helper (C2.3) and setup-file mode exist only for TVs
  that cannot do this (like the 2014 reference); verify it on the device first (PORTING-WITH-AI, runtime capabilities).

### A4.2 Start rules

- **PROF-2** Start route, in this order: no account/setup → sign-in (dev) · account without profile/server data → `start` ·
  exactly one profile → Home if it has no PIN (and a token), else the picker · last profile was kid/teen and "Profile switch
  needs PIN" is on → Home in that kids profile · else by **Start profile** (`main` = main profile, `last` = last used if it
  has no PIN, `picker`; default `main` with a setup file, `picker` without). No plex.tv request in the start path when tokens
  are cached. [?] Whether `main` with a PIN-protected main profile asks for the PIN at start.
  *Accept:* unit tests for each branch; kids profile + PIN switch on → app starts in the kids profile.
- **PROF-3** Profile kinds: `main` (owner, admin), `kid` (restriction `little_kid`/`older_kid`), `teen` (`teen`), `''`
  (other Home users, treated as adults). Kids and teens count as "kids" for UI rules. Content filtering is done by the
  server through the profile's own token. Profiles are only the owner and Plex Home users: accounts the server is merely
  shared with ("friends") are never offered, stored or turned into profiles – their tokens are discarded when read, and
  such entries in an old setup file are skipped.
- **PROF-4** Activating a profile: set server base + that profile's token for all requests (including images), clear image
  queue/cache, load that profile's settings (defaults merged at runtime, only own changes stored), start other-servers
  checks, then Home. A 401 from the **active** server (Home, library, details, album, artist) drops only that profile's
  token. Adult profile → the profile picker (toast "Please choose your profile again"; setup mode: "Please run the setup
  again"). Kids/teen profile while "Profile switch needs PIN" (PROF-7) is on → **never the open picker** (it would let a
  child switch to an adult profile without the PIN): the app goes to Home, which shows the state "Please choose your
  profile again" with the button "Choose profile"; that button asks for the main profile's PIN first, like every other way
  to the picker. A 401 from another server never touches the own profile (SRV-2).

### A4.3 PINs

- **PROF-5 PIN pad:** 4 digits, checked automatically after the 4th; digits via number keys or on-screen pad. **5 wrong
  tries → 30 s lockout** with countdown, counted per profile across dialog close/reopen; network errors don't count; a
  result arriving after cancel still counts as a failure. *On-device sign-in:* only 400/403/422 from the plex.tv switch
  call count as a wrong PIN; a plex.tv 401 means the account token is invalid → dialog "Please sign in again", no failed
  try counted. The picker re-reads the profile list (with the PIN flags) in the background each time it opens (at most
  every 30 s), so a PIN newly set in Plex applies at once.
- **PROF-6 App PIN (setup-file mode):** the Plex profile PIN cannot be checked without plex.tv, so each profile can get its
  own **app PIN** that applies only to this app on this TV. Stored as PBKDF2-HMAC-SHA256(PIN, 16-byte random salt,
  1000 iterations, 32 bytes) per profile in `pins.json` `{v:1, setup:<server machineIdentifier>, reset:<createdAt>,
  p:{uuid:{s,h,i}}}`; the PIN itself is never stored. PINs belong to the **server** (kept on re-setup, dropped for another
  server); `resetAppPins: true` in a setup file wipes them once per setup. An unreadable PIN file fails closed (every
  profile protected, no PIN matches); while it is unreadable, the PIN pad's help line says so – no PIN can match until the
  setup program is run again with "Reset app PINs". Setting or removing an app PIN writes the PIN file **immediately**;
  "PIN saved" / "PIN removed" appears only after the write succeeded. If it fails, the previous PIN state is restored and
  the user is told it did not work (never a confirmation for a PIN that is not stored). Hashing runs asynchronously with a
  visible spinner. A port MAY raise the iteration
  count on faster hardware (store `i` per entry, as the reference does).
- **PROF-7 Profile switch needs PIN** (`pinsw`, per TV): available when the main profile has a PIN and a kid/teen profile
  exists; default on. A kids profile then needs the main profile's PIN to reach the picker (sidebar profile entry,
  Settings › Switch profile).
- **PROF-8** "Protect adult profiles?" reminder when restricted profiles exist and the main profile has no PIN – at most
  once a week ("Later").

### A4.4 What kids profiles cannot do

- **PROF-9** Kids/teen profiles have: no Profile & account and no Diagnostics category, no "Customize home screen" /
  "Customize sidebar", no Discover/watchlist, no screensaver settings, no subtitle search, no library refresh; "Ask if
  you're still watching" after 2 episodes / 1 hour; error texts add "Please ask a grown-up."; own empty-home text.
  Admin-only (main profile): profile-switch PIN, refresh libraries, start profile, all app PINs, setup info.

### A4.5 Signing out and changing the account

- **PROF-10** *On-device sign-in (ports that sign in on the TV, PROF-1/C1):* Profile & account offers, main profile only,
  **Sign out** ("This removes the Plex account from this TV; your watch progress stays on the server.", confirmation with
  Cancel preselected) and **Sign in with another account** (sign out, then the plex.tv/link PIN sign-in, then server
  choice and profile picker). Signing out deletes every stored token, the server choice, cached profile data and
  per-profile caches of this account on the TV; per-TV comfort settings may stay. Switching between profiles of the same
  Plex Home stays **Switch profile** (no new sign-in, PIN rules PROF-5 … PROF-7). In setup-file mode (the 2014 reference)
  these actions are replaced by the setup row "Run the setup program again" (a new account = new setup on the computer).
  *Accept:* after Sign out, no token remains in storage and the app starts at sign-in; another account signs in without
  reinstalling; kids/teen profiles never see these actions.

## A5 Home

- **HOME-1 Layout:** hero on top (background art of the focused item, overline, title, meta, summary; for started shows a
  season strip when "Show episode progress" is on) and a vertical stack of horizontal rows below. Card kinds: landscape
  16:9 (Continue watching, Next episodes), poster 2:3, square (music/audiobooks). Focus anchor: card top at y = 372; the
  focused row stays at that y, rows scroll under it. The hero follows focus only after **300 ms** at rest.
- **HOME-2 Rows** (each switchable, per profile): Continue watching (`/hubs/continueWatching/items`), Next episodes
  (`/library/onDeck`), Continue listening (audiobook libraries only), "New in {library}" per movie/show library (40 fetched,
  de-duplicated per show, max 12), optional server hubs per library (one `/hubs/sections/<id>?count=12` per library with
  enabled hubs, titles in the app language via `X-Plex-Language`), playlists. Default: Continue watching, Next episodes,
  newest per library; everything else off. `/library/onDeck` also returns started **movies**: Next episodes shows
  **episodes only**, and while Continue watching is on, only episodes not yet started (started ones are in Continue
  watching), so no title appears in both rows; within the row each show appears once.
- **HOME-3 Loading:** paint immediately from the per-profile home cache (≤ 60 KB), then refresh in the background (each
  request independent; a failed row keeps its old content). Without a cache show a static skeleton. Refresh again after
  playback stops, after a library scan, at most every 60 s on re-entry, and when a library changes (HOME-12). The focused
  row is never rebuilt (NAV-7.3). An answer that arrives while another screen is on top is applied on return and counts as
  old as its request (not as fresh): if that is more than 60 s ago, Home asks again (TV test 29.10.: a show had arrived,
  but "New in Shows" stayed stale after a visit to the library, because a parked answer counted as fresh).
  After playback the server needs a moment to process the "stopped" report: refresh **1.5 s** after returning, and while
  Continue watching (or, with it off, Next episodes) does not yet contain the video that was just stopped (not finished,
  own server), do **not** apply that answer – nothing disappears – and ask again after 2.5 s and 5 s; the last answer
  counts (a finished video legitimately leaves the row).
  *Accept:* cold start with cache shows content before any network answer; stopping an episode halfway and returning to
  Home keeps it in Continue watching (first, with the new progress).
- **HOME-4 Customize home screen** (`homerows`): list of all available rows (base rows + "New in" per library + hub catalogue
  discovered in the background via `/library/sections`, `/hubs/sections/<id>?count=6`, `/hubs?count=6`), each with a switch,
  Yellow = move, last row "Restore defaults" (confirm). Rows that are temporarily unavailable keep their place and switch.
  Optional build-time modules (none in the standard edition) may add rows with ids starting `x-`: always off by default and
  listed after the others; they may add "Add a row …"-style entries above "Restore defaults" and mark rows as removable (Red =
  remove, confirm with focus on "Keep"). While removable rows exist, "Restore defaults" asks what happens to them: "Cancel"
  (focused), "Keep my rows (switched off)" (defaults plus those rows off at the end) or "Reset everything (delete my rows)"
  (saved list cleared). On Home such a row first shows its header with a short note ("Loading …", no cards,
  focus ring hidden, hero unchanged) and is only fetched once it comes near the focus (rows R−1 … R+2, from the idle queue);
  its cards are titles outside the server (OK/INFO open the page for those titles, no watched/hide actions); it can grow at its
  end; it is never written to the Home cache.
- **HOME-5 Hide from Continue watching:** Red removes the card locally at once, toast "Hidden · Red: undo" (6 s); the server
  call (`PUT /actions/removeFromContinueWatching`) is sent only after **6 s** (or immediately on exit/leaving). Red again
  within 6 s = undo. The delayed call uses the server and token captured when Red was pressed – also when it is sent early
  because of a profile switch or exit (never under the next profile's token).
- **HOME-6 Watched/unwatched** (Yellow, DET-4): in landscape rows the card disappears (NAV-7.1).
- **HOME-7 Activation:** OK on a landscape card plays with the "Started videos" rule (ask/resume/start); OK on posters opens
  details; PLAY always resumes; PLAY on a show plays its next episode. TOOLS: Play · From start · Choose version (if > 1
  file) · Mark watched/unwatched · Hide (Continue watching) · anime entries · Info.
- **HOME-8 States:** server down with nothing cached → "Can't reach Plex server" with a 10 s retry countdown and Try again;
  rows already shown → toast "Offline · retrying", retry every 10 s, "Connected again". Empty server: "Nothing here yet";

- **HOME-9 Clock** top right (setting `clock`), updated once a minute; uses the corrected clock (A12.3).
- **HOME-10 Clock style** (setting `clockStyle`, per profile; dimmed while `clock` is off): *In a box* (default, 24 px

  size, weight and `text-2` colour as the season-tab arrow of DET-3) sits right after the heading (and count) of the
  partly visible next row; on the last row there is none. No setting (it is a single quiet glyph). It is part of the
  next row's heading, so pointing at or clicking it behaves like the heading: one row down. When the next heading is
  not on screen (a tall poster row pushes it below the fade), the same arrow sits at a fixed spot bottom left (x 144,
  y 656, on the hint bar's line, which is right-aligned) followed by the next row's title in `text-2` (max 400 px, "…"),

  focus step, no measuring.

- **HOME-12 Library changes:** the server's own change signal decides when Home refreshes rows outside the 60 s re-entry
  rule. `GET /library/sections` returns per library a change counter `contentChangedAt` (older servers: `updatedAt`); every
  answer to that request (Home's own refresh included, no extra cost) is compared with the last known one; the first
  answer per server and profile only sets the baseline. While Home is the top screen (and, in optional modules, while they
  wait for something to arrive) the app asks for it itself at most every **2 min**, in the idle queue after key rest,
  never while a video plays or the screensaver runs, never two at once – one small request (≈ 1–3 KB). When a library
  changed, Home fetches **only the affected rows**: "New in {library}" and server hubs of that library plus Next episodes
  (Continue watching, playlists and module rows stay as they are). The answer is applied in place at rest with the rules
  of NAV-7.3 – no skeleton, no reload of the screen, hero and focus stay; the focused row's new version waits until focus
  leaves it or 30 s pass without a key, and replaces it at once if the focused title was removed from the server. A replaced row that is still at its start (never scrolled into) stays at its start, so titles that are new at
  the front are visible; a row the user had scrolled into keeps the same card at the same place. If another screen is on top, the affected rows are fetched when Home is entered again (unless the full
  60 s refresh runs anyway). A failed partial fetch stays silent and is retried on the next visit. The server raises the
  counter as soon as it takes in a new file, but lists the title under "recently added" only after matching it (TV test
  30.10.: still missing 16 s after the signal, there about 1–2 min later) and does not raise the counter again – so Home
  fetches the same rows again **30 s, 60 s and 120 s after each answer** (three re-checks; a new change starts them over;
  while another screen is on top a due re-check waits for the return). A change noticed while a load is running is fetched
  right after it (the running load may have read its lists before the change). *Accept:* with Home
  open and focus on row 1, a new show arriving in the "Shows" library appears in "New in Shows" (another row) within 4 min (up to 2 min until the
  check, plus the time the server needs to match the title)
  without the focus, hero or row 1 moving; focusing that row and leaving it again is not needed for other rows.

  - *Detection:* only the server's own change signal (HOME-12): every answer to `/library/sections` is compared with a

    the library ("New in") or Home (lists). Empty list: "Nothing here right now". **View:** every such grid offers the
    library's view sizes **Large · Medium · Small · List** (same card sizes, same list columns as LIB views): one chip
    **"View"** ("Ansicht") above the grid (reached with ▲ from row 1) and Red open a panel with the library's "View" tab; TOOLS

    rest of a "Show all" visit) and switching it does not load the list again; it starts in the default library view (setting `libView`, otherwise Large).
  - *Back:* RETURN in the opened screen (from grid row 1) goes back to Home – not along the section history (NAV-5) – and
    Home restores its focus on the "Show all" card (NAV-6).
  - *Performance:* the card is part of the row's model and is rendered by the normal card pool (no extra DOM, no image, no
    request) – the target is only loaded when it is opened. It is never written into the Home cache (other readers – search suggestions, screensaver – only see real titles); the row keeps its target there and the card is re-added when Home reads the cache.
  - *Accept:* in "New in Movies", ▶ past the last poster focuses "Show all"; OK opens Movies sorted by "Recently added ·
    for this visit only", newest first; RETURN lands on the card again; opening Movies from the sidebar afterwards shows
    its usual sort.

## A8 Search, Discover and watchlist

### A8.1 Search

- **SRCH-1** On-screen keyboard (abc/123, space, delete) **and** number keys (T9, 900 ms window) type into the field (max 60
  characters). The query runs **400 ms** after the last input, from 2 characters, aborting the previous request
  (`GET /hubs/search?query&limit=10&includeCollections=1`, LRU of 20 queries). Results as rows per group: shows, movies,
  episodes, people, collections (music hidden; people de-duplicated). The keyboard layout follows the UI language: German
  has an umlaut row (ä ö ü ß) on abc, English has none there (the umlauts sit on 123). Pressing a keyboard key, choosing a
  recent term or leaving the screen first commits a pending T9 letter, so it is never lost.
- **SRCH-2** Before typing: "Recent searches" (per profile, newest first; setting `recentSearches` = how many terms are
  remembered: Off, 4, or 8 by default – 8 terms of normal length fill the two chip lines of SRCH-6) and below it
  suggestions from the home cache (0 requests). Off remembers nothing and deletes the stored lists of the profile (Search
  and Discover); switching to 4 keeps the 4 newest. A missing, empty or unknown stored value counts as 8, never as Off. Discover keeps its own
  list with the same rules. When typing (also T9 digits while a recent term has focus) replaces this view with results,
  focus moves to the keyboard – it never stays on a hidden chip.
- **SRCH-3** Red = clear the typed text, hint "Clear text" (on a focused recent term: remove that term, SRCH-6). Query and result focus survive opening
  a result and coming back.
- **SRCH-4** No results: "Nothing found for “{q}”" + spelling tip.
- **SRCH-5 Pointer in Search and Discover** (NAV-2): pointing at a fully visible result row focuses it without scrolling;
  a row that is partly visible (≥ 40 %) comes up after 250 ms of rest or on a click; the keys and "Recent searches" take
  the focus without moving the results. Edge zones over the result width: top y 52–96 while scrolled, bottom from y 604
  (or the top of a partly visible row that is not pointable) to 656 while another row follows; one step = one group,
  the focus comes along.

- **SRCH-6 Compact recent searches**: the terms are chips side by side (32 px high, 12 px apart, line step 44 px) that
  wrap into **at most 2 lines** over the 656 px result width; a term is at most 300 px wide, longer ones end in "…"; the
  last chip is always "Clear history" (outlined). If not everything fits, the oldest terms are left out (they stay
  stored), so the suggestions keep their room. Keys: ◀▶ within a line (◀ at a line start → keyboard), ▲▼ to the chip with
  the nearest centre in the other line, ▼ from the last line → first result row, ▲ from the first row → first chip of the
  last line; ▶ at the keyboard's right edge → first chip. **Red on a focused term removes only that term** (hint
  "Remove"; focus stays at the same place, rows below move up if a line disappears; last term gone → keyboard).
  "Clear history" asks first (dialog, Cancel preselected), then empties the list, focus → keyboard, toast "Search
  history cleared". Pointer: each chip is hit-tested by its own rectangle in page coordinates; pointing focuses without
  scrolling (NAV-2, SRCH-5), click = OK. Chip widths are measured once per term when the empty view is built (never in
  the key path); removing a term reuses them.

### A8.2 Discover

- **DISC-1** Optional (setting `discover`, default on for the main profile, never for kids). Same view as search, query after
  **700 ms**. In parallel: own search, and per type `GET /library/metadata/<anchor>/matches?manual=1&title&agent=
  tv.plex.agents.movie|series&language` on the PMS (anchor = first title of a movie/show library; the PMS asks the Plex
  metadata service – no plex.tv from the TV). Then **one** `GET /library/all?guid=<g1>,…` (max 30) to find own copies.
  Groups: "On your server – play" and "Not on your server · Movies | Shows". If the outside search fails: toast "Only results
  from your server"; results are cached only when complete. Rules that keep the groups honest:
  - If the own-copy check (`/library/all?guid=`) fails, **all outside results are dropped** – unverified, an own title
    could show as "Not on your server". Only own results are shown, with the toast "Only results from your server", and
    nothing is cached.
  - A result is complete (and cacheable) only if the own search, both type queries and the own-copy check succeeded. If no
    outside search was possible, the text never claims the catalogue was searched ("Not found on your server. Searching
    beyond your server isn't possible right now – please try again later."). Own search and outside search both failed →
    the server error state.
  - The anchor is looked up once per profile and type and remembered; a 404 on `matches` (anchor deleted meanwhile)
    forgets it and looks it up **once** more (no loop).
  - `matches` is slow (the PMS asks an outside service): its timeouts never count towards offline detection (NET-1).
- **DISC-2 Inspiration** (before typing): rows such as top/rediscover/recently released/genre of the day from the own
  server (one `/hubs/sections/<lib>?count=20` per library, genre picked by a hash of day + profile), plus plex.tv rows
  "Trending now", "Just released", "Coming soon" **only with the helper**. Customizable (`insprows`). With "Only titles you
  don't have yet" (default on) the plex.tv rows hide owned titles (also titles on other servers, if enabled; a slow other
  server is skipped after 6 s); a row with nothing left shows a friendly note. A row change (▼/▲) touches only the old and
  new row (PERF-14); the row that enters the window below is filled one card per frame in rest, a slot that gets a new row
  is reused without being emptied first. Target: no frame > 50 ms on a row change [T] (2014 reference with the previous
  code: one frame of 59–182 ms per ▼; after the rework 56.1 fps with 4 frames > 50 ms, worst 100 ms, of which 19 ms was the
  focus ring forcing a layout when it reappeared [M]). The focus ring never reads layout (PERF-14): when it appears again
  after being hidden, it jumps without a transition and gets its transition back two frames later.
- **DISC-3 `extdetails`** for titles not on the server: the same first screen as an own movie/show (hero with background,
  poster, overline "Movie · Not on your server", title), meta "year · … · not playable here", **no Play**, watchlist
  add/remove (with helper), Back. What else it shows comes from DISC-5.
- **DISC-5 Details of a title not on the server.** One request per opened title (cached in memory, 30 titles, per title +
  language): with a helper that offers `details` (C2.3) → `GET /details?id=<hex>&lang=` = the Plex catalogue entry. It fills:
  summary (2 lines with "…", INFO = full text), meta line (movie: year · runtime · content rating · rating; show: year ·
  n seasons · "Still running"/"Ended" · content rating · rating; then "not playable here"), up to 3 genre chips, after
  them one line "Director: …" (movie; else "Studio: …") or "Network: … · Created by: …" (show), a **Cast** row below (cast
  cards with photo + role, ▼ scrolls the page like an own title; OK does nothing) and the background (catalogue art sharp,
  else the poster blurred). INFO adds tagline, director/writer, network/studio, all genres, seasons/episodes and the
  release/first-aired date. Images of foreign titles are `https` URLs of known image hosts; the TV loads them through the
  PMS photo transcoder (`/photo/:/transcode?url=…`, checked live with catalogue, TMDB and person images), lazily like all
  row images. Without a helper (or an older helper without `details`): **no request**; the page shows what the PMS
  search returned (year, type, summary) and – only if the summary is empty – a friendly line that says what the helper
  would add and where to set it up; helper not answering → a line saying so (open again later); otherwise "No
  description available.". An optional extension may add a second source (data model of `N.disc.emptyInfo`); the Plex
  catalogue wins, the extension only fills empty fields. It may also replace the short line after the genre chips
  ("Network · Created by …", which stays in INFO) with its own text, e.g. when the next episode airs. If the extension shows its own state on the page (overline, meta
  line), INFO shows the same overline and state, never a contradicting "Not on your server"; while the extension says its
  state is still coming (at most 2.5 s, no buttons yet so nothing jumps), a small spinner stands where the buttons will be,
  so the page never looks frozen. A port with direct plex.tv access calls
  `metadata.provider.plex.tv/library/metadata/<id>` itself.

### A8.3 Watchlist (helper)

- **DISC-4** Only when a helper is configured (setup file `helper` or dev config): probe `GET /neo-helper` (3 s; needs
  `watchlist: true`), then row "Your watchlist" in empty Discover and the button in `extdetails`. Adding/removing a title
  in `extdetails` updates "Your watchlist" without a request as soon as Discover is shown again (added = first card,

## A9 Video playback

### A9.1 Start and decision

- **PLAY-1 Entry:** `play(item, how)` with how = ask | resume | start. OK on Continue watching/Next episodes follows the
  "Started videos" setting (ask shows a dialog "Resume at {time}" / "From start"); PLAY resumes without asking; menus offer
  "From start". Double start within 600 ms is ignored. Music stops first.
- **PLAY-2 Sequence:** `GET /library/metadata/<rk>?includeMarkers=1&includeChapters=1` → automatic track choice (PLAY-9; if it
  differs from the server's selection: `PUT /library/parts/<id>?audioStreamID&subtitleStreamID&allParts=1`, awaited) →
  decision `GET /video/:/transcode/universal/decision` (15 s timeout) → direct play: file URL; otherwise HLS
  `start.m3u8`.
- **PLAY-3 Decision query:** `protocol=hls, fastSeek=1, copyts=1, location=lan (wan for other servers), directPlay,
  directStream, directStreamAudio=1, mediaIndex, partIndex, subtitles=none|burn, offset, session = X-Plex-Session-Identifier`
  plus all `X-Plex-*` identification values. **Client profile extra** describes what the device decodes; on the 2014 TV:
  HEVC never direct, H.264 ≤ 8 bit / level 4.1 / 1920×1088, `DirectPlayStreamSelection=true` (a non-default audio track does
  not force a remux), SRT as subtitle target. **Never send `hasMDE`** (the PMS then ignores the profile). **A bitrate limit
  only when really transcoding** (any `maxVideoBitrate` blocks direct play of files whose peak is higher); the limit comes from
  "Quality when converting". Other servers (always treated as over the internet, `location=wan`, SRV-3): cap 8 Mbit/s
  1080p already in the decision, and **no direct play attempt** – the first attempt is HLS (direct stream or transcode); a player error before the first time tick (also a
  connection error of the player) walks the PLAY-5 chain before an error is shown.
  A port MUST build the profile extra from the device's real capabilities (C1).
- **PLAY-4 Modes shown to the user:** direct play, direct stream (container changed), transcode – with the reason in plain
  words in the INFO panel (e.g. "Converting: HEVC isn't supported by this TV", "Converting: subtitles are burned in").
- **PLAY-5 Fallback chain:** player render error → retry as direct stream (`directPlay=0`) → transcode (`directStream=0`) →
  error screen (title/text per error kind, INFO = decision reason + technical details, buttons Try again / Lower quality /
  Back). "Lower quality" lowers the setting one step. Every restart at the same position (fallback, track switch that
  needs a new session, quality change) resets the position mapping for the new session: a transcode started with `offset`
  may report time relative to its start, direct play reports file time – decide anew per session, never carry the old
  base over.
- **PLAY-6 Versions:** several `Media` → automatic choice (1080p H.264 8-bit > 720p > other H.264 > HEVC > rest; highest
  bitrate ≤ quality limit; anime with a Japanese track preferred when anime rules apply). Plain text per version
  ("1080p · H.264 · 4.2 GB / plays directly" – an estimate). A user choice is kept per title for the session only.
- **PLAY-7 Timeline:** `/:/timeline` on every state change and every 10 s; while transcoding and paused/buffering also
  `/video/:/transcode/universal/ping` every 10 s (the PMS kills an idle transcode after ~20 s). Stop: `state=stopped` +
  `/video/:/transcode/universal/stop`. Watched: the PMS marks it from the timeline at ≥ 90 %; when playback moves on to the next
  episode before that point (e.g. up next during the credits), the app sends `/:/scrobble` for the finished episode. A `terminationCode` in the timeline answer ends playback with a toast. All writes go through one
  write function that a read-only/demo mode can suppress.
- **PLAY-8 Resume:** start at `viewOffset` minus "Rewind when resuming"; after a pause > 1 min also rewind by that value. A
  safety jump ~550 ms after the first time tick corrects players that ignore the start offset. After playback stops, a
  details page reloads its data **without** cached episode lists (TV test 30.10.: the cached list still had the position
  from before playback, so Play after STOP started at 0:01 without the resume question). The app also remembers where the
  last video was stopped on this TV: for 10 min, if the server still reports an earlier position for that title (it has
  not processed the stop yet), the remembered one is used (not when it counts as watched; marking watched/unwatched forgets it).

### A9.2 Tracks and subtitles

- **PLAY-9 Automatic choice**, in this order: (1) remembered per show (setting `rememberTracks`, up to 200 shows, oldest
  dropped) or per movie; (2) anime rules (A9.3); (3) preferred audio language + subtitle mode. Audio description and SDH
  tracks are **never** picked automatically. The app's setting wins over the server's default selection, except "As on the
  server". Remembered choices apply per track type: if only the audio track was remembered, subtitles follow the subtitle
  mode (step 3), not the server's selection.
- **PLAY-10 Subtitle modes:** Off · Foreign parts only (forced track in the audio language, only if that is the subtitle
  language) · With foreign audio · Always (missing language → the other one; none → off) · As on the server.
- **PLAY-11 Subtitle paths:** image subtitles (PGS/VobSub/DVB) and ASS with "Burn into picture" → `subtitles=burn`
  (transcode). Embedded text subtitles in direct play → the player's own text track, drawn by the app in its own box.
  External SRT (`Stream.key`) → parsed and drawn by the app. In a transcode on the 2014 TV subtitles are always burned
  (its HLS has no subtitle tracks). Look: size (S/M/L/XL), colour (white/yellow), background (dimmed/black/none), position
  (bottom/a bit higher), offset (−3…+3 s). A port SHOULD render text/ASS tracks natively (libass where available) and burn
  in only image subtitles the player can't show.
- **PLAY-12 Track names in plain words:** language name in the app language (from `languageCode`, never the server's
  text), codec + channels ("Dolby Digital Plus 5.1", "AAC Stereo", "DTS-HD MA 7.1"), "foreign parts only" / "styled";
  sub-line: audio description / for the hearing impaired / commentary / track title (only if names collide) / burned in /
  default.
- **PLAY-13 Switching during playback** (Green/SUBTITLE/OSD, panel with Audio | Subtitles tabs): switch locally when the
  player can (direct play audio), otherwise restart the session at the same position (also when switching to/from burned-in
  subtitles). "Remember per show" also saves the choice on the server (PUT, PLAY-2).
- **PLAY-14 Subtitle search** (main profile, not kids): `GET /library/metadata/<rk>/subtitles` (30 s); download
  (`PUT …/subtitles?key=`) only after a warning dialog.

### A9.3 Anime rules

- **PLAY-15 Detection per title** (`animeDetect` normal | strict | off). Strong signals: library/label/collection/genre
  "Anime", Japan as the only country + Animation, Japan + Animation + Japanese track. Weak: Japan + Japanese track (ignored by
  "strict"). Signals come from detail data (one GET per show/movie, cached). A per-profile manual mark ("Treat as anime" /
  "Not anime" in TOOLS) overrides all signals.

- **PLAY-17 Skip intro/credits** (markers from the server; needs server-side analysis): "Offer" shows a button "Skip intro

- **PLAY-18 Up next:** a countdown card ("Wait before next episode", default 10 s) appears at the final credits marker,

### A9.5 Seeking and OSD

- **PLAY-22 Seeking model:** ◀▶ and the −x/+x buttons add "Skip length (arrows & buttons)" (5/10/15/30 s or asymmetric
  −10/+30 s; holding ×3 after 1 s, ×6 after 3 s), FF/RW add "Skip length (FF/rewind)" (10/30/60 s or −15/+30 s) – unless
  *FF/rewind keys in videos* is set to *Fast-forward & rewind* and the video plays directly (then PLAY-32). The
  buttons show the real values ("-10", "+30"). The target shows at once on the bar ("+2:30 → 41:12"); **one** jump is executed
  **600 ms** after the last press. Digits 1–9 = 10–90 %. Pointer: moving over the bar previews time (and thumbnail), a click
  sets the target through the same accumulator (one jump after 1 s rest; moving on corrects it); resting on the bar can open
  fine scrubbing (PLAY-30). Seek preview images
  (setting `thumbs`) from `/library/parts/<id>/indexes/sd/<ms>` via the image transcoder 240×135, 2 s raster, max one new
  image per 250 ms; fallback: load the whole BIF file once and slice it.
- **PLAY-23 OSD:** islands without animation; time/bar updated at most once per second and only while visible. Top: title,
  clock + "ends at" (while paused both keep running: redrawn once per minute on the minute, "ends at" = now + remaining time). Bottom control island (x 64, y 556, 1152 × 128): bar (6 px, 10 focused, marker segments, chapter
  ticks), times, chapter name, centre group **⏮ · −x · Play/Pause (64 × 56, centred at x 640) · +x · ⏭** and right group
  Chapters (if any) · Audio & subtitles · More; label above the focused button. ⏮/⏭ appear only in pairs and only when there
  is something to change: episodes (play queue built from the show, so earlier episodes are included, also without autoplay),
  videos of a "Play all" queue, or chapters of a movie with ≥ 2 chapters (⏮ more than 3 s into a chapter = its start).
  Chapter maths tolerate player lag (the reference player reports its position up to ~1 s late and seeks in whole
  seconds): a position up to 2 s **before** a chapter start already counts as that chapter, and a jump to a chapter start
  with ⏮/⏭ (except 0:00) targets start + 1 s – so ⏮ never skips and ⏭ never repeats a chapter.
  At the first/last item they are dimmed and not focusable. ⏭ by hand does **not** mark the episode watched. The same button
  family (sizes, signs, labels) is used in Now playing (MUS-6). Shows on any key, hides after 5 s (3 s at
  start), stays while paused (mini hint bar B/C/D/INFO in the time line) and while a panel is open.
- **PLAY-24 Keys:** OSD hidden – OK = skip button if shown, else OSD (focus Play/Pause); ◀▶ = seek; ▲ = OSD; ▼ = OSD with
  bar focus; RETURN = stop; CH▲/CH▼ = ⏮/⏭. OSD visible – ◀▶ between buttons; ▲ to the bar (◀▶ = preview, jump on OK or 1 s rest) and the
  skip button; RETURN hides. Always: digits, PLAY/PAUSE/STOP/FF/RW, Green/SUBTITLE, Yellow chapters, Blue sleep, INFO
  technical info, TOOLS More.
- **PLAY-25 More menu** (RETURN steps back to it): Version · Quality (direct play shows "Original (direct)"; another value
  restarts as a transcode at the same spot) · Picture size (Automatic / Original / Fill 16:9 / 4:3 / Zoom) · Subtitle look
  (only with subtitles on) · Skip intro/credits · Autoplay · Sleep timer · "Problem with playback?" (Reload · Force
  conversion · Lower quality · Technical info) · Search subtitles. Values apply to this session including following episodes;
  defaults live in Settings.
- **PLAY-26 Chapters:** list with start time and, if the server has them, 96×54 thumbnails; generic names become
  "Chapter n".
- **PLAY-27 Pointer:** any movement shows the OSD; the first click only shows it; buttons, bar, skip button, cards and mini
  hints are clickable; a click on a free area toggles pause.
- **PLAY-28 Connection lost** (network gone while playing): pause, island "Connection lost" / "The video is paused. It
  continues at the same spot once the connection is back." (Try again / Exit), check every 5 s, then restart at the saved
  position with "Connected again".
- **PLAY-29** The TV's own screensaver is off while video plays and back on in pause/after the end.
- **PLAY-30 Fine scrubbing** (setting `ptrLoupe`, default **off**, only with pointer control): purpose – a pointer click on the
  bar lands within ±26–53 s on a 2 h movie (6.6 s per px, pointer jitter ±4–8 px); the goal is ±15–30 s at minimum and as
  close as the jitter allows, without extra steps. Form: one of three styles (PLAY-31), all on the same logic; the default
  is the **panel above the bar** (A). Nothing magnified is ever placed *below* the main bar: under it the time row and the
  button row are too close together for the coarse Smart Control pointer (a former "fine bar under the bar" style was
  removed after the TV test for exactly that reason). Trigger: pointer rests on the bar
  **700 ms** with movement ≤ 8 px **and** the finger on the touchpad (raw pointer events within the last 1 s); never while
  moving along the bar, after a key, with a pending jump or an open panel. Span: ±4 % of the bar's duration, clamped to
  ±1…±5 min; **off** when the coarse bar already has < 1 s per px (short episodes, music tracks). Window: 480 px (Now
  playing 400 px) centred on the rest point, clamped to the bar; mapping anchored so the rest point keeps its time (no jump
  on opening); linear inside, sticky at the ends; 3 px hysteresis, whole seconds, chapter starts snap within 6 px. Common
  look: main bar dimmed with the magnified range highlighted (A/D: two wedge lines from that range to the tab), ticks
  (30 s/1 min or 10 s/30 s), chapter gaps and marker segments, played part, accent knob or target line at the pointer.
  The first 3 times (counter per TV) the hint "Fine scrubbing – move up to leave" is shown (A/D: tab header, B: label slot
  under the buttons), then "Fine scrubbing · ±4:48 min".
  **Capture band and button guard:** while fine scrubbing is open, every pointer event inside its band belongs to it – the
  band reaches from its top edge (A/D: the tab's top edge; B: 32 px above the bar centre) down to the **bottom of the
  control island**, i.e. it covers the time row *and the button row*. There the buttons neither take focus nor react to a
  click; a click anywhere in the band sets the fine target, a click that leaves (or lands outside) only closes it – a click
  while fine scrubbing is open never activates a button. Leaving sideways (more than 24 px past an end) only counts at bar
  height and above (above the bar's hit zone bottom, y 501); below it the time sticks to the window ends, so slipping
  sideways never leaves the pointer "live" over a button. Geometry (1280 × 720 video OSD, chosen for ±4–8 px jitter): bar
  centre y 485 (hit zone 469–501), time row 500–526, button hit zone 530–594, island bottom 638; A's fine bar sits 64 px
  above the bar centre (y 421, 48 px clear of the bar's hit zone), D's at y 422; the corridor around the rest point is
  ≥ 32 px in every direction before anything closes (B: exactly 32 px up; A: 107 px up, D: 189 px up; all: 153 px down) –
  at least 4× the jitter, while the fine bar stays within one short thumb movement of the main bar. Leave: pointer up out
  of the band (the touchpad re-touch point in the screen centre counts as up, and so does any jump of more than 200 px
  between two moves), down below the island, sideways at bar height, any key (RETURN only closes fine scrubbing), OSD
  timeout without finger on the pad; afterwards the dwell is disarmed until the pointer moves > 8 px. Click = target
  through the seek accumulator (PLAY-22: one jump after 1 s rest, swiping corrects). Motion: fade/slide in 120 ms
  (opacity + translate, none with reduced motion), out at once. Cost per pointer move: 2 transforms + 1 text node, drawn
  once per frame; all elements pooled and laid out only when it opens. Remote: no fine mode (◀▶ already step 5–10 s).
- **PLAY-31 Fine scrubbing style** (setting `loupeStyle`, default **Panel above the bar**; dimmed until PLAY-30 is on):
  three looks on the same logic (dwell, span, anchored mapping, hysteresis, snapping, band and button guard, leaving,
  click), each equally precise. A stored value of the removed style `bar` (fine bar under the main bar) is dropped when the
  profile loads, so it falls back to the default A. Now playing always uses the stretching bar (B): text sits above its bar
  and the buttons right below, so there is no safe room for a second bar or a panel (MUS-6). Shared rule: nothing
  overlaps – a style either attaches to the control island from above or stays exactly on the bar; motion is
  opacity/transform only, 120 ms ease-out, none with reduced motion, closing at once.
  - **Panel above the bar** (A): a tab of the window width + 2 × 16 px and 80 px height grows out of the top edge of the
    control island – its bottom edge *is* the island's top edge (no overlap of the two translucent surfaces), top corners
    rounded, 12 px concave fillets join it to the island (left out within 12 px of an island corner). Content: header
    (hint/title of PLAY-30, centred, ellipsis), fine bar 6 px with ticks/gaps/segments/knob, below it start | target |
    end (the ends give way to the target, so the hint never meets the times). Opening: the tab slides up out of the
    island edge (clip at the edge, translate only). Main bar dimmed with range + wedge lines up to the fine bar's ends on
    the tab's bottom edge. **Wedge lines** (A and D): drawn once per opening into one canvas behind the range (no rotated
    boxes – on the 2014 engine those had uneven, jagged, cut-off ends): anti-aliased, 2 px, round caps, mirror-identical
    left/right; the foot sits *on* the range's top corner (2 px inside, never overlapping the bar), the colour `wedge` runs
    from full at the foot to 45 % at the tab, so no line ends hard in empty space; they only fade with the panel;
    the time row stays. While open, only what the tab really covers gives way: subtitles move up by the tab height + 8 px,
    the skip button / up-next card / last-episode card hide only if their box intersects the tab (also when they appear
    while it is open), the preview image sits above the tab (y 207). The band reaches up to the tab's top edge.
  - **Stretching bar** (B): no extra element – an overlay exactly on the bar in three parts: left of the window
    compressed, the window stretched to its full width (lighter track, ticks above the bar, accent target line at the
    pointer), right compressed; chapter gaps, marker segments, played part and playhead are drawn with this piecewise
    mapping. The opening animation shows the stretch: each part starts transformed back onto its coarse position
    (scaleX/translateX, the playhead by translate) and runs to the stretched one, so every point moves linearly from its
    coarse to its stretched place – that motion is what tells the user the bar got finer. Time row stays; target time in
    the preview image or the time bubble at the pointer; hint/title in the label slot under the buttons.
  - **Filmstrip** (D): like the panel, but the window is 1000 px wide (same span → about twice as fine) and the tab
    (162 px high, 8 px side margin) holds 7 preview images of 136 × 77 px with 8 px gaps covering exactly the window –
    image k is section k, so the image under the pointer is always the selected one (3 px accent frame, moved by
    transform). Each image shows the middle of its section; the selected one shows the target spot (at most every
    250 ms, same 2 s image grid as the seek preview, so the browser cache hits). Loading: after the 120 ms opening,

    Without preview images (no `indexes="sd"` on the part, or *Preview images when skipping* off) the panel is used.

### A9.6 Fast-forward, rewind and playback speed

- **PLAY-32 Fast-forward and rewind (trick play):** setting `ffrw` (*FF/rewind keys in videos*): **Skip** (default) – FF/RW
  jump as in PLAY-22; **Fast-forward & rewind** – FF/RW change the speed of the picture instead.
  - *Scale:* one scale **−16× · −8× · −4× · −2× · 1× · 2× · 4× · 8× · 16×** (the steps the 2014 player accepts; the list is
    data – `config.json` `trickSpeeds` – so a TV test can trim or extend it). FF moves one step to the right, RW one step
    to the left: from 8× forwards RW gives 4×, 2×, normal (1×), then 2× backwards. At either end of the scale a further
    press changes nothing. From pause, FF/RW resume and scan (without the extra jump back of *Rewind when resuming*,
    PLAY-8, and without its toast). Silent; subtitles are hidden. Key repeats closer than 250 ms
    apart are ignored, so a held key does not race through all steps.
  - *Indicator:* a light pill (height 28, radius 14, `text-1` background like the playhead, FF or RW icon and "8×" in `on-accent`, 20 px
    semibold) centred in the time row of the control island – the place of the seek target, which never shows at the same
    time. The controls stay visible while scanning; time and bar keep updating (at most once per second). The Play/Pause
    button shows Play, its label reads "Play normally".
  - *Keys:* PLAY, RETURN and OK (on Play/Pause, on the bar or with hidden controls) play on normally at the current spot;
    moving between the buttons (◀▶ in the button row, ▲▼) keeps scanning. Every other action – PAUSE, ◀▶ on the bar or
    with hidden controls, digits, ⏮/⏭ and CH▲/CH▼, colour keys, TOOLS, INFO, OK on another button, a pointer click, STOP –
    first returns to 1× and then does what it always does. STOP, CH▲/CH▼ and ⏮/⏭ leave the video right away, so they return
    to 1× without an extra `playing` timeline report just before `stopped`. A click on Play/Pause or a free area only
    returns to 1×. While scanning, the "last episode" card and the up-next countdown are hidden.
  - *Edges:* rewinding into the first seconds (the next time tick would land before 0:00) returns to 1× from 0:00.
    Fast-forwarding into the last seconds (less than about 0.6 s × speed left, at least 3 s) returns to 1×, so the end plays
    as usual (credits countdown, next episode, PLAY-18); an end event while scanning **forwards** is a normal end. An end
    event while scanning **backwards** means the start was reached: the video plays on from 0:00 at 1× (no watched mark,
    no autoplay). The player may send that end event only about a second *after* the return to 1×, so for 4 s after
    rewinding stops an end event counts as the start too, unless the position is within the last 10 s. The jump back to
    0:00 is rounded down (never to before the start). Skip-intro/credits
    buttons and the countdown are hidden while scanning and re-armed afterwards like after a seek (PLAY-17).
  - *Only for direct play:* the 2014 player can scan only files it plays directly (B-6). In a direct stream (repackaged
    or audio adjusted) or transcode the keys jump as in PLAY-22, and the first press per video shows "Fast-forward only
    works with direct play – skipping instead." (after RW: "Rewinding fast only works …") for 4 s in the label slot under
    the buttons. If the player refuses a step once, nothing is capped (from 1× that press jumps instead); if it refuses the
    same step a second time, the scale is capped there for this video; if that was the first step, the keys jump with
    "Fast-forward doesn't work with this file – skipping instead." (after RW: "Rewinding fast doesn't work …").
  - *Server and progress:* while scanning the timeline reports `state=playing` with the current position (every 10 s and
    once more when scanning ends); buffering events during scanning neither change the state nor report `buffering`.
    Stopping while scanning saves the position reached (`state=stopped`). A render error falls back as usual (PLAY-5) and
    restarts at 1×.
  - Music and audiobooks keep their jumps (PLAY-22, MUS-6): the 2014 audio player has no trick mode. Why Skip is the
    default: it behaves the same in every video, while scanning depends on how the file is played; the reference's trick
    mode still awaits its TV test [?]. *Ports:* use the platform player's trick mode or seek preview with the same keys,
    scale and pill; on platforms with a speed control the scale is the outer part of PLAY-33.
- **PLAY-33 Playback speed (platform capability – not available on the 2014 reference TV, B-6; the reference implements
  only trick play, PLAY-32).** A port whose player can change the tempo SHOULD offer one speed scale per player:
  - *Scale:* **−32× · −16× · −8× · −4× · −2× · 0.5× · 0.75× · 1× · 1.25× · 1.5× · 1.75× · 2× · (2.5× · 3×) · 4× · 8× ·
    16× · 32×**, with 1× in the middle. **0.5× … 2×** play **with sound, pitch preserved** (the voice does not get higher
    or lower: e.g. `preservesPitch` in HTML5 media, `PlaybackParameters` in Media3, `audioTimePitchAlgorithm` in
    AVFoundation); 2.5× and 3× only where the platform keeps speech intelligible (test with the human). All negative steps
    and everything above the audio range are **silent trick play** with the rules of PLAY-32 (pill, subtitles hidden,
    edges, timeline, any other action returns to 1×). Steps the device cannot play are left out (capability check, as
    PLAY-32's `trickSpeeds`). Subtitles stay on in the audio range (shifted with the tempo).
  - *Where the value lives:* **video – per playback session:** a new speed applies to this video and the episodes that
    autoplay after it, and resets to 1× when the player closes (like the More menu values, PLAY-25). Reason: almost
    everything is watched at 1×; a faster pace usually belongs to one sitting, and a speed left over from yesterday would
    surprise. **Audiobooks – remembered per book** (per profile, key = audiobook, max 200 books, oldest dropped), new books
    start at the global setting *Audiobook speed* (default 1×). Reason: the right pace depends on the narrator and the
    book, and listeners keep it for many hours. Audiobooks offer only the audio range (no silent steps). **Music –
    no speed control** (always 1×).
  - *UI, video:* a **Speed** button (gauge icon at 1×; at any other speed the button shows the value, e.g. "1.5×"; label "Speed" or "Speed · 1.5×") in the right group of the button
    row: Chapters · **Speed** · Audio & subtitles · More (PLAY-23 geometry, 64 px grid). OK opens the **speed panel**: an
    island 1024 × 152 above the control island (x 128, y 290, 16 px gap; `osd` background, radius `r.xl`) with the title "Speed" and
    the current value, one row of step chips (44 × 40, gap 8, radius `r.md`, `surface-3`; text 18 px semibold): left the
    silent backwards steps, the audio range in the middle with **1×** wider (72 × 40, label "Normal" below it), right the
    silent fast steps. A 4 px line under the audio range in `text-2` with the caption "with sound" and thin lines under the
    silent ranges with "without sound" (`text-3`) explain the difference. Focus: chip in `accent` with `on-accent` text,
    scale `fo.scale` like the buttons; the chip of the active speed carries a 3 px `accent` underline. ◀▶ move the focus
    and apply the speed at once (time, bar and "ends at" follow); OK or RETURN closes; PLAY sets 1× and closes. FF/RW
    (setting *Fast-forward & rewind*, or always where the platform has no jump habit) step along the **coarse** part of the
    scale (−32 … −2 · 1 · 2 … 32) without opening the panel: from an audio speed such as 1.5×, FF goes to 2×, RW to 1×.
    While a speed ≠ 1× is active and the controls are hidden, the clock island shows it ("21:34 · ends at 22:41 · 1.5×",
    "ends at" divides the remaining time by the speed); silent speeds show the pill of PLAY-32.
  - *UI, audiobooks (Now playing, MUS-6):* a **Speed** button between Chapters and Sleep (chapter back · −x · play/pause ·
    +x · chapter forward · chapters · **speed** · sleep); the same panel with the audio range only (0.5× … 2×/3×), the
    button label shows the value; Now playing's time row shows "1.25×" next to the remaining time.
  - *Accessibility:* everything works with keys alone (◀▶ OK RETURN); every chip is a pointer target (≥ 44 × 40, clicks
    apply and close); focus is never shown by colour alone (scale + accent fill); values use the app language's decimal
    separator ("1,5×" in German); "with sound"/"without sound" are written out, not only shown as line styles; reduced
    motion: no scale animation.

  gapless playback and speed control (audiobooks: PLAY-33).

## A11 Other servers

- **SRV-1** Optional: libraries of servers that **someone else shared** with a profile, next to the own server. Configured
  in the setup program per profile (each server checked from the computer: reachable / not reachable / "https required" →
  not selectable). The own server keeps working without plex.tv.
- **SRV-2** Address check per server in the background 2.5 s after profile activation: `GET /identity` without token (5 s),
  `machineIdentifier` must match; then `/library/sections` with the server's token (20 s) → its libraries (cached per
  profile, shown at once on the next start). No address works → ask the helper's `/servers` for fresh addresses (if it
  offers `servers`), else state "down"; 401/403 → "no access". Requests to other servers use at least 25 s timeout, never
  sign the own profile out on 401 and never trigger the offline bar. A single failed or timed-out request is **not** an
  outage: the app first re-checks that server's `/identity` (10 s, one retry); only if that fails too is the server "down"
  (address forgotten, looked up again on next use after 30 s). A playback start error on a server whose `/identity` still
  answers is a playback error (Try again / Lower quality), not "server unreachable". Checks started under a previous
  profile are dropped on a profile switch (callers waiting on them are released, never left hanging).
- **SRV-3** Items remember their server; images, playback (decision with `location=wan`), play queue, subtitles, thumbnails
  and connection checks use that server's address and token.
- **SRV-4 UI:** sidebar entries with "from {server}"; library overline "Other server · {name}"; details overline
  "… · {name}"; no "Refresh library". Errors only inside that library/detail page with Try again. Settings › Profile &
  account › Other servers shows "n of m reachable". Not yet: home rows and search from other servers.

## A12 Screensaver, clock, accent colour, library background

### A12.1 Screensaver

- **SAV-1** After "Screensaver after" (Off/1/2/5/10/15/30 min, default 5) without input – never during playback, during
  pause at the earliest after 10 min; the time counts from the last key, the end of playback or the last change of screen
  (e.g. back on a show page after an episode), never from before a video – a full-screen layer above everything shows pictures and the clock. Any key ends it
  **without** triggering a function; a pointer click is swallowed. Pointer movement alone does not end it and never focuses
  or scrolls the screen behind it; a press ends it and the whole click (down, up and the click that follows) is swallowed,
  so nothing under the pointer opens or plays. Not in kids profiles (they get the defaults).
- **SAV-2 Sources:** "Libraries" (default; random titles with background art from the chosen libraries – none = all movie and
  show libraries, music = artist pictures; optional unwatched only) or "Home screen" (from the home cache, 0 requests).
  Library source: one count request per library (`Container-Size=0`), then one random page of 30 per refill
  (`sort=titleSort`, random start). Pictures appear in random order with movies and shows mixed **evenly**: the chosen
  libraries take turns, in a new random order each cycle and never the same library twice in a row – regardless of their
  size (540 movies next to 64 shows still means every second picture is a show); a title skipped as a video still (SAV-5)
  is replaced from the same library. Each library keeps its own supply with
  titles from up to 3 of its pages; each new page is shuffled and scattered at random among them (a single page alone
  would be 30 alphabetical neighbours). Shown titles are remembered per library, so nothing repeats within a library until
  all of its titles were shown; then that library alone starts a new round (a small library repeats earlier than a big
  one). A library that yields no picture in a whole round is not asked again. Up to 3 page requests per library at the
  start (one per picture change), then one request per 30 pictures of a library. Errors → home pictures and 1 min rest. If the picture supply runs empty while a refill is still
  loading (slow server), the screensaver waits for it and continues as soon as it arrives – it never stays on one picture.
- **SAV-3 Transitions:** Cut · Crossfade (default, 1.5 s) · Fade through black · Slow zoom · Slow drift · Zoom through ·
  Curtain · Blinds · Tiles · Random (never the same twice, never Cut). "Reduce motion": moving ones → crossfade. The next
  picture is loaded and decoded behind the visible one before any transition starts (never a black frame). Blinds = 8 strips
  from the left, Tiles = **3 × 2** tiles in random order (each part its own layer; 4 × 3 = 12 tiles ran at 48 fps with one
  156 ms frame on the 2014 reference [M], so the tile count was halved; 3 × 2 then ran at 60.2 fps but still with 3 frames
  > 50 ms, worst 89 ms [M]; parked outside the picture: 57.5 fps / 3 frames > 50 ms, worst 78 ms [M] – a parked layer is not
  painted until it enters the picture). The parts are created once when the screensaver starts and stay their own layers
  above the picture at opacity 0: the next picture is put on them before the transition (painted while invisible and
  nothing moves), the transition only sets each part's opacity transition and opacity 1 – no z-index or display change and
  no layout read when it starts. After every transition the work is staged: swap the layer order at once, reset the old
  layer, free its picture and hide the parts 400 ms later, load the next picture 1.5 s after that (decoding a full-screen
  picture takes 70–90 ms on the 2014 reference [M] – never during a transition). The layer order is set by **document
  order**, not only by z-index: after each swap the front layer is also moved to be the later of the two (and for Curtain the
  incoming layer before it starts). The 2014 reference at times stopped honouring z-index changes on these layers after the
  screensaver had run for a while; the old layer then stayed on top, the cleanup turned it black over the new picture and the
  next picture appeared early under the previous title [M]. Target ≥ 55 fps, no frame > 50 ms during the visible transition [T].
- **SAV-4 Overlays:** Ambient (default: clock 72 px light, title, meta line on a soft corner shadow) · Classic box · Movie
  poster (big title bottom) · Lower third · Big clock · Small clock only · Off. The overlay moves with every picture
  (corners in turn, 4 positions) **against burn-in**: it fades out before the picture changes, is moved and re-drawn while
  invisible and fades in only once the new picture fully stands (Cut: all in one frame) – the new title never shows over
  the old picture, and re-drawing its text never falls into a running transition (2014 reference: 47–78 ms per re-draw [M]).
  Exception: the first picture after the start (fading in from black, nothing underneath) shows its overlay together with
  the picture. Text contrast ≥ 4.5:1 even on white pictures. "Show clock" applies to
  every style. Option: blur pictures (default on). The darkening behind the text always reaches the screen edges it
  touches, in every position: corner shadows sit exactly in their corner (one pre-rendered image per corner, no mirroring
  at run time), the bottom band of Movie poster / Lower third stays at the bottom edge and only the text moves; the text
  keeps its safe-area offset. Shape of the darkening: a soft shadow that follows the text (sum of bell curves on the text,
  alpha = peak · (1 − e^(−k·field)), no plateau, no visible edge, egg or rectangle on bright pictures; fades to 0 before
  every image edge that is not a screen edge; ±½-step noise against banding); only as dark as needed (behind the text
  ≥ 0.34 for primary text, ≥ 0.45 for the softer sub line on a white picture). Small clock only has its own small shadows
  in display size (never a scaled corner image). The bottom band of Movie poster / Lower third is 520 px tall and rises
  gently (smootherstep over 310 px from y 200) to only 0.5, so on a white picture the brightness changes by at most 0.25 L*
  per pixel and its top edge never reads as a line; all text starts at y ≥ 504, where the band is already at 0.5.
- **SAV-5 Picture kind ("Screensaver pictures"):** Real backgrounds only (default) · Also video stills · Posters and covers.
  When a title has no designed background, the PMS extracts a frame from the video file and serves it as the title's `art`
  (a *video still*: random moment, often dark, blurred or letterboxed). Lists and detail pages look the same for both
  (`art` = `/library/metadata/<id>/art/<time>`); only `GET /library/metadata/<id>/arts` tells them apart: the entry with
  `selected` true has a `ratingKey` starting with `media://` (…`.bundle/Contents/Art/art1.jpg`) for a still, and
  `metadata://art/…` (agent art: tmdb/gracenote/plex/fanarttv) or `upload://…` for a real picture; nothing selected and only
  `media://` entries = still, otherwise unknown = treated as real; art that is not a PMS path (or a failed request) counts as
  real. Measured on a real library [M]: about 70 % of the movies had a still selected (all sampled ones 1280 × 720 or
  1279 × 720, real ones mostly 1920 × 1080 to 3840 × 2160), every show and artist had agent art. Check cost: one request per picture (17–35 ms at the PMS, 2–50 KB), only inside the screensaver
  in its idle phase before the next picture loads, one at a time, the response text searched without full JSON parsing,
  result kept in memory per `art` path (errors not kept). "Real backgrounds only" skips stills; after 12 stills in a row it
  shows the poster of the first one instead (never a black screen). "Posters and covers": the sharp poster/cover (360 × 540,
  music 460 × 460) on the same picture 640 px wide, strongly blurred and darkened by the PMS (`blur`, `opacity` 35 % over
  black, at most 89/255, so all overlay text keeps ≥ 4.5:1 without help; no extra dimming layer, and the overlay's own
  darkening image is hidden for poster pictures so nothing ever lies over the poster), placed opposite the text for corner overlays, centred above the band for Movie poster / Lower
  third, otherwise centred; square pictures 15 % smaller. Big clock: poster and clock form one group that is centred
  horizontally as a whole – poster on the left, a 56 px gap, then a fixed 440 px clock slot with the digits centred in it
  (the clock is always HH:MM; a fixed slot keeps the group from shifting every minute and needs no text measuring);
  the poster's centre lines up with the digits' centre; the four burn-in positions move the whole group. A soft,
  pre-rendered shadow lies under the poster (`saver-shadow.png`, square covers `saver-shadow-sq.png`, stretched to the
  poster; no CSS shadow or blur), slightly offset downwards, fading to 0. Every transition works with it (Blinds/Tiles
  draw the poster, its shadow and the background as three backgrounds per part, identical to the layer below). "Blur
  screensaver images" does not apply to this mode. **Paused video** (SAV-1) shows the paused title by the same setting:
  Posters and covers → its poster; Real backgrounds only → its background picture, checked once with the same `/arts`
  request, and its poster instead if that picture is a video still; Also video stills → its background picture; without a
  background picture its poster in every mode (and only the text when it has neither).
- **SAV-6 Long runs ("Clock only after a long time"):** 1 h · 2 h (default) · 4 h · Never; unknown or missing values count as
  2 h. Once the picture screensaver (not the paused-video one) has been running that long, it stops changing pictures: no
  further loads or library/`/arts` requests, the current picture fades to black (opacity of the front layer, 1.5 s, never in
  the middle of a transition – a running one finishes first), then both picture layers and all Blinds/Tiles parts are
  released (images set to a blank placeholder, part backgrounds removed). The overlay keeps moving with only the clock (no
  title or sub line, no darkening image – it is black anyway); with the clock off or overlay "Off" the screen stays black.
  Any key ends the screensaver as usual; the next screensaver starts with pictures again. Why: on the 2014 reference the
  screensaver ran for about 8 hours (≈ 1000 full-screen pictures plus one `/arts` request each) and the TV then froze
  completely after a key press – not even the power button worked; most likely the browser's native memory, which the app
  cannot measure there [M]. Black also protects the screen from burn-in and saves power. Between pictures only the visible
  picture stays referenced: the cleanup stage after a Blinds/Tiles transition (SAV-3) also removes the picture from the
  hidden parts. Diagnostics: every 30 min of a running screensaver, at the switch and at the end of a run ≥ 30 min one
  warning line goes to the log (`saver heartbeat|night|end <minutes> min, <pictures> pics, img …` with the image-queue
  counters and the current step) – release builds keep only warnings and errors, so a later freeze can be dated from the last
  line. Watchdog: if loading the next picture or a transition makes no progress for 2 minutes (at least twice the picture
  interval + 15 s) – on the reference TV a picture once stayed for 50 minutes because one frame, image or network event
  never arrived – the screensaver logs `saver stuck <step> …`, drops whatever was still running and carries on with the next
  picture; the picture on screen stays. While a picture change starts, a pending move of the overlay (no new picture in time)
  is cancelled, so the old title never reappears over the new picture.

### A12.2 Library background

- **BG-1** Setting `libBg`: Off · **Colour mood** (default: a soft 4-corner gradient from the server's `UltraBlurColors` of
  the focused title, computed on the device as a 16×9 image, 0 extra requests) · Title picture (the title's art from the
  image transcoder at 320×180 with `blur` and `opacity` over the background colour) · Random picture (one per opening of the
  library). Strength Subtle (default) / Stronger; text contrast stays ≥ 4:1 (subtle) / ≥ 3:1 (stronger) for secondary text.
  The colour mood keeps only part of a title's colourfulness (subtle 35 %, stronger 70 % of each channel's distance to its
  grey), so a strongly coloured poster tints the background instead of flooding it.
  Changes only after **600 ms** without input, cross-fade 400 ms (instant with Reduce motion), never while a key is held.
  "Background images" off → title/random picture show the colour mood. Computing the gradient image and starting the change
  take ≤ 5 ms on the slowest device [T] (2014 reference: 18–23 ms per change with the first code, 4.7–20 ms after the buffer
  rework, of which 6–19 ms was building the 32×18 image [M] – hence 16×9, a quarter of the bytes; the GPU scales it up
  smoothly, so it looks the same): one reused byte buffer, the fixed PNG header encoded once, checksums in the same pass
  that writes the pixels, a cache per colour set. The tables and the first run through the code are done once in the idle
  queue when a library opens, and the image for the focused title is computed in the idle queue (160 ms after the last
  key) – the change after 600 ms only takes it from the cache (2014 reference before: 4–8 ms, peaks 12.5 / 23.5 ms [M]).

### A12.3 Clock correction

- **CLK-1** TV clocks can be wrong (observed: 7 h off). The app derives an offset from the HTTP `Date` header of normal
  server answers (only answers with round trip ≤ 1.5 s; median of the last 5, used from 3 samples, applied only if > 90 s,
  changed only when it moves > 2 s). Displayed times (clock, "ends at", screensaver) **and every comparison with a
  timestamp from the server** use it – e.g. the audiobook pause length of MUS-3 (now − the track's `lastViewedAt`; with a TV
  clock hours off, the raw clock would rewind after every pause or never). Durations and timers measured on the TV itself use
  the raw clock. Time zone/DST come from the TV. A port on a platform with NTP MAY drop this.

### A12.4 Accent colour

- **ACC-1** Per profile, 7 colours (A16.2), the brand colour first; takes effect immediately. Every colour passes the
  contrast checks (dark text on it ≥ 4.5:1, itself ≥ 4.5:1 on the background). The pointer image follows the colour. The
  colour of the last profile is remembered for the start screen and picker (no colour jump).

## A13 Offline, errors and diagnostics

- **NET-1 Offline detection:** two network errors/timeouts in a row on the active server → offline; then `GET /identity`
  every 10 s (4 s timeout); any HTTP answer (also 4xx/5xx) = reachable. Aborted requests and other-server requests don't count,
  nor do requests that the PMS forwards to an outside service (Discover `matches`, DISC-1) – a slow metadata service is not
  a server outage.
- **NET-2 Offline bar:** top centre, not focusable: "“{server}” isn't answering · retrying in {n} sec" → "Connected again"
  (3 s). Hidden in the player (PLAY-28 handles it).
- **NET-3 HTTP rules:** own timeout per request (default 8 s; decision 15 s; timeline 4 s; other servers ≥ 25 s); retries
  only for GET (2×, after 500 and 1500 ms) on network/timeout/5xx; at most 3 requests in parallel; identical in-flight GETs
  (same URL + token) are merged; 401 → token handling (PROF-4).
- **NET-4 Error kinds and texts** (title / text / buttons): network, server ("Can't reach Plex server" / "Your server
  “{server}” isn't answering. Is it switched on and awake? Retrying in {n} sec."), sign-in (dev), auth ("Please sign in
  again"), profile ("Please choose your profile again"), generic ("Something went wrong" / "{app} is restarting this view."),
  setup ("Please run the setup again"), setup damaged. Buttons: Try again, Sign in, Choose profile, Exit, OK, Learn more.
- **NET-5 Diagnostics log:** ring buffer of 500 lines; persisted in two rotating files of 64 KB; release builds keep only
  warnings/errors. Tokens, PINs, sign-in codes and public IPv4 addresses are redacted **before** storing (also URL-encoded
  forms). "Send log" (only on request) POSTs to a configured receiver on the home network; "Delete log" clears it. A JS
  error storm (> 3 in 10 s) shows "Something went wrong".
- **NET-6 Connection test** (Settings › Help & info): 3× `/identity` (median latency), server version, `/library/sections`
  for access – summarized in plain words.

## A15 Text and i18n

- **TXT-1** All UI text comes from string tables (German and English; the reference checks key parity, identical

- **TXT-2 Tone:** friendly, short, no jargon; explain **what** a thing does and **why** (settings descriptions, empty and
  error states always say what the user can do). Beginners must understand every text. Technical terms only in INFO panels.
- **TXT-3 Consistent terms** across UI and docs: Continue watching, Next episodes, Recently added/New in, Watched/unwatched,
  Audio & subtitles, Sort & filter, Skip intro/credits, Sleep timer, Discover, Watchlist, Other servers, Setup program,
  Helper, App PIN, Main profile, Kids profile, Screensaver. Button names in docs MUST match the UI.
- **TXT-4 Length limits** (characters, without placeholders; enforced at build): hint 14 · toast 40 · nav 15 · dialog title
  32 / text 160 / buttons 18 · error/empty title 40 / text 200 · settings category 18 · settings label 34 · settings
  description 160 · home row title 32 · overline 40 · profile sub-line 14 · card sub-line 30 · screensaver line 24 · menu
  entry 34 · help text 600. Both languages MUST fit; single lines ellipsize, boxes have ~10 % reserve for wider fonts.
- **TXT-5 Formats:** 24 h clock HH:MM; durations rounded to minutes ("1 hr 2 min"); rating "x.x/10" with the language's

### A16.4 Focus styles

- **VIS-1** Cards: one ring element moved with a transform + the card scaled 1.08 (150 ms ease-out `cubic-bezier(0,0,0.2,1)`);
  captions sit **outside** the scaled card and only change colour. Buttons/chips/keys/tabs/panel entries: accent fill, dark
  text and icon. Settings rows: 3 px accent frame on `surface-3`. Labels above focused icon buttons (player, now playing).

### A16.5 Motion

- **VIS-2** Transitions ≤ 150 ms (focus, row scroll, sidebar); fades 400 ms (background), screensaver 1.4–1.6 s. While a
  key repeats (< 200 ms) nothing animates. "Reduce motion" removes zoom/slide. Only transform and opacity are animated;
  never layout properties, never animated shadows.

### A16.6 Scaling to 1080p and 4K

- **VIS-3** Design in the 1280 × 720 reference grid and scale **uniformly**: 1920 × 1080 → × 1.5 (16 px → 24 px, card
  176 × 264 → 264 × 396, ring 4 → 6 px); 3840 × 2160 → × 3. Platforms with density-independent units (Android dp at
  960 × 540 dp, tvOS points at 1920 × 1080, web apps at 1920 CSS px) map the reference px × 1.5 to their 1080p unit.
  Request images at the **scaled** display size (e.g. poster 264 × 396 at 1080p; hero 1920 × 1080) so the image transcoder
  delivers exact sizes. Keep safe areas proportional (5 %). Do not add content density when scaling – the layout and the
  number of visible cards stay the same, so the screenshots remain valid references.

### A16.7 Missing images

- **VIS-4** Missing pictures never show as grey boxes. A card, cover or mini-player tile without a picture – or whose
  picture fails to load – shows a **title card**: a colour derived from the title (stable, from the same small set as the
  avatars; a track uses its album's colour, so grid, album page and mini player match) with the title or its initial. A
  show without any art: title card as poster, the first episode's still as background. An album or artist with an empty
  title is shown as "Untitled". Tracks without an own cover use the album cover, never the artist picture. Backgrounds without art
  (Home hero HOME-1, details DET-1, Now playing MUS-6) use the server-blurred poster/cover at 1280 × 720, centre-cropped (no
  upscaling on the device). Double-buffered pictures (hero, backgrounds): if the hidden layer already holds the requested
  URL, swap at once – most engines fire no load event for an unchanged source, and waiting for one leaves the old picture
  standing.

### A17.2 Rules that make the budgets reachable (2014 build; keep them where the platform is slow)

- **PERF-14** Per focus step touch only the **old and new** element (class change) plus **one** ring transform and **one**
  container transform. No layout reads, no `innerHTML`, no z-index changes, no image decode, no storage write in the key
  path. Everything else waits for an idle queue (160 ms after the last key or pointer step, slices ≤ 6 ms); a pointer step
  counts as input like a key, so idle work, image assignment and storage writes never run between two pointer steps.
- **PERF-15** Fixed element pools: 11 cards per row, 4 row slots on Home, a fixed grid window per view (25 cards in the
  Large poster view; all views in the geometry table of A16.1); recycle only cards that
  leave the window. Fill new cards **one per frame**. Captions are their own small layers. A row that has to disappear
  (Home: the row above the focused one sits under the hero text) is hidden by opacity 0 on its card area, which is a
  permanent layer without content of its own – not by `visibility`, which makes the 2014 engine drop and later re-paint
  every card layer of the row in the frame of the ▲ key [T].
- **PERF-16** The hero, the library background and similar big images change only after rest (300 ms / 600 ms) and in a
  frame of their own; two image elements alternate so there is never a hole.
- **PERF-17** Cache first: Home, hub catalogue, library state, other-server libraries and track choices are cached per
  profile so a start needs no network to show content.

## A18 Privacy and security

- **SEC-1** No telemetry, no ads, no analytics, no third-party services. In daily use only the user's PMS is contacted
  (plus the optional helper, and other servers the user enabled).
- **SEC-2** The Plex password and Plex PIN are only ever entered on plex.tv (browser or official link page), never in the
  app or the setup program.
- **SEC-3** Tokens: one server-bound token per profile; revocable on plex.tv (Authorized Devices). Tokens MUST NOT be
  logged (redaction, NET-5), MUST NOT be sent to the helper and SHOULD be kept in secure storage on platforms that have it.
  On the 2014 TV tokens travel in URLs (player limitation, Part B); a port SHOULD send them as headers.
- **SEC-4** Plain HTTP only inside the home network: own-server addresses MUST be private IPv4 (RFC 1918, link-local,
  loopback); public addresses, names and https are rejected for the own server on the 2014 build (it can't do modern TLS).
  Other servers use IPv4 literals only. A port with TLS SHOULD prefer the PMS's https (`plex.direct`) addresses.
- **SEC-5 Helper network rules:** fixed routes mapped to fixed plex.tv URLs (allow-list, C2.3) – never an open proxy; https
  with certificate checks, no redirects, 10 s timeout, 256 KB answer cap; only private-network clients (optionally only the
  TV's address); shared key from the setup file; per-client rate limit; Host header must be an IP literal (DNS rebinding);
  plex.tv tokens stay in the helper; answers are slim JSON without tokens.
- **SEC-6** The setup program's page is only reachable from the computer itself (Host/Origin/CSRF checks); it hands the app
  package only to devices on the home network; access data stays in memory. Its install (sync) server accepts only an
  IP-literal or absent Host header (DNS rebinding) and serves the package – which contains the profile tokens – only to
  the device that fetched `widgetlist.xml` first.
- **SEC-7** Kids safety: PROF-5…PROF-9. App PINs are hashed (PROF-6).
- **SEC-8** Diagnostics leave the TV only on explicit request and only to a home-network receiver.

## A19 Accessibility

- **A11Y-1** Minimum text size 16 px at 720p (24 px at 1080p); body text contrast ≥ 7:1, secondary ≥ 4.5:1 (library
  background stronger: ≥ 3:1 for secondary text); accent colours are contrast-checked (ACC-1).
- **A11Y-2** "Reduce motion" setting (VIS-2). No flashing content.
- **A11Y-3** Labels above focused icon-only buttons; every icon button has a text label.
- **A11Y-4** Subtitle size, colour, background and position are adjustable; audio description and SDH tracks are labelled

- **A11Y-5** Long press and the clickable hint bar make every key reachable with a pointer remote that lacks keys.
- **A11Y-6 [?]** The 2014 TV has no screen reader API used by the app. A port SHOULD expose labels to the platform screen

## C2 Data and API contracts

All PMS requests send `X-Plex-Token` (the active profile's or the other server's) and identification headers
(`X-Plex-Client-Identifier` = the setup's client id, `X-Plex-Product`, `X-Plex-Version`, `X-Plex-Platform`,
`X-Plex-Device`, `X-Plex-Language`), and ask for JSON (`Accept: application/json`). Writes go through one function that a
read-only/demo mode can suppress.

### C2.5 Local storage (per TV)

`state.json` (client id, last profile, language, start profile, profile-switch PIN, pointer settings, remembered accent;
account/server/tokens only in development builds) · `settings-<uuid>.json` (only values the profile changed) ·
`pins.json` (PROF-6) · `cache-home-<uuid>.json` (≤ 60 KB) · `cache-hubs-<uuid>.json` · per-profile files for library
state, recent searches, track choices, anime marks, other-server libraries · rotating log files.

Writes are debounced (2 s). A failed write (exception, or a false result where a file system exists) is never treated as
saved: the file stays pending, is retried with growing delay (doubling from 4 s, at most 60 s) and logged. Data whose
confirmation the user sees (app PINs, PROF-6) is written at once, and the confirmation waits for the result.

## C3 Test strategy

1. **Unit tests (Node, no DOM, no network):** all pure logic – decision query and fallbacks, versions, track rules and
   names, markers/countdown, seek accumulation, OSD layout/navigation, start rules, PIN state machine and hashing,
   `setup.json` validation, home-row merge, library queries, search/T9, row/grid geometry, screensaver logic, colour mood,
   clock correction, i18n rules. Synthetic fixtures in `tests/synthetic`; the build runs every test.
2. **Visual scenes:** `npm run visual` renders ~200 states with synthetic data and a mock PMS in a headless browser and
   compares them with approved baselines (tolerance 24 per channel, ≤ 0.2 % of the area, clock masked). The scene list is
   the parity checklist for a port.
   **Layout check** (runs with every visual scene, alone: `npm run layoutcheck`): right before the screenshot the live
   DOM is inspected – text boxes of different elements must not overlap (tolerance 2 px, only where both are actually
   visible), text must not be cut off without "…"/line clamp, must not lie on a button or card it does not belong to, must
   stay on the 1280 × 720 screen and inside the title-safe area (rows that deliberately bleed over the right edge excepted),
   coloured panels must not partly overlap, and a toast must not cover text. Deliberate cases are listed with a reason in `tools/layout_allow.json` or
   marked `data-layout-ok`; every other finding fails the run, with a report and screenshot crops. A self-test page with
   planted errors guards the check itself. A port should run an equivalent check on its own screens.
3. **On-device benchmarks:** A17.3 – required before every release on the slowest supported device.
4. **Player matrix on the device** against a real PMS: H.264 8-bit MKV/AC3, MP4/AAC, H.264 High@5.1, Hi10P, HEVC 8/10-bit,
   4K, DTS, TrueHD, multi-audio with an audio-description track, external/embedded SRT, SDH, ASS, PGS, two versions of a
   title, with/without intro and credits markers, chapters. Per file: expected decision, start time, seeks, track switches,
   up next, timeline/watched state visible in other Plex apps, and the transcode session removed after stop.
5. **Spec check:** `npm run spec:check` (part of `npm test` and CI) keeps this document in sync with the code.
