There are two ways a port can appear here:

- **Linked** (the default): the entry links to the port's own repository. The port is entirely its author's
  responsibility.
- **In the collection** (optional, marked *in the collection* in the table): the author submitted the app, the maintainer

## Policy – please read before installing a port

- **Linked ports: we only link.** For them this repository hosts **no binaries**; each link goes to the port's own
  repository or releases page. We list them in good faith but do not review, test or support them. Problems with a
  linked port belong in that port's issue tracker.
- **Ports in the collection** went through the review below. Their downloads here are built by the maintainer from the
  reviewed source – never the submitter's own binary. *maintainer-tested* means the maintainer ran the smoke test on a
  real TV of that kind; *community-tested* means the result rests on the submitter's test-plan results. A review lowers
  the risk, it is no guarantee: the licence's "no warranty" applies, and the author stays responsible for the code.
- **Check before you install.** Prefer ports with public source code; compare checksums with the ones the author publishes
  (for downloads from the collection: `SHA256SUMS` in the same release);
  only install apps from sources you trust. Sideloading usually needs your TV's developer mode – switch it off again when
  you no longer need it.
- **No Plex branding, no impersonation.** A port must not use "Plex" in its name or icon, and must not look like or claim to
  be an official Plex app. Describe it as "an unofficial client for Plex Media Server" and keep the trademark notice. The
  same goes for other media servers: a Jellyfin or Emby variant uses neither their names nor their logos as its own.
- **Privacy and security rules of the spec apply:** no telemetry, tokens never logged or sent anywhere but the user's own
  server (SPEC A18, SEC-1 to SEC-8), plain HTTP only inside the home network, and the helper rules if a port uses a
  helper (SEC-5). Ports that break these rules are removed.
- **"Built against an older spec"** is shown automatically when a port's `specVersion` is older than the current spec –
  it may miss features or fixes added since then. Maintainers update `specVersion` and `lastVerified` with a pull request.

## Add your port

1. Open an issue with the **Port submission** form, or send a pull request that adds one entry to [`ports.json`](ports.json)
   (format: [`ports.schema.json`](ports.schema.json)). Set `specVersion` to the version shown at the top of SPEC.md when
   you built it, and fill `features` with your status for each Part A section (`done`, `partial`, `planned`, `n/a`).
2. Run `npm run spec` – it validates the entry and regenerates this page and the website table. `npm test` fails if the entry
   is invalid or this page is out of date.
3. A maintainer reviews the entry against the policy above and merges it.

Built the app for a media server other than Plex (Jellyfin, Emby)? Add `"mediaServers": ["jellyfin"]` to your entry
(how to build such a variant: section 10 of the [porting playbook](docs/PORTING-WITH-AI.md#10-using-another-media-server-jellyfinemby)).

## Submit your app for the collection

Voluntary, and only if you want your finished app to be offered as a download here in addition to (or instead of) your own
releases. One person maintains this project, so reviews take time and happen when there is time – there is no deadline.

### What to submit

Open an issue with the **Collection submission** form. It asks for:

1. **Source code** – a public repository and the exact tag or commit to review. All of it: the build must not need any
   file that is not in the repository (except the TV platform's own SDK). **No binaries are accepted without source.**
2. **Build instructions** – one command per package, the tools and versions needed (for example the TV platform's SDK),
   and your own build with its SHA-256 checksum, so the maintainer can compare.
3. **Platform description** – a short `platform.json` in the repository root:

   ```json
   {
     "id": "lg-webos",
     "brand": "LG",
     "modelFamilies": ["OLED C1 (2021)"],
     "osVersions": ["webOS 6.0"],
     "installChannel": "developer mode, sideload with the webOS CLI",
     "mediaServers": ["plex"],
     "specVersion": "1.0.6",
     "tested": { "date": "2026-10-30", "models": ["OLED C1"], "testPlan": "full" }
   }
   ```

4. **Test-plan results** – the filled-in results template of [TEST-PLAN.md](docs/TEST-PLAN.md) (section 6): at least the
   device setup checklist, the smoke test and the privacy and security checks; ideally every applicable test.
5. **Install guide** for that TV – beginner-friendly and step by step like [docs/INSTALL.md](docs/INSTALL.md), in
   English (a German version is welcome). Pictures as drawings or screenshots with demo content only.
6. **The list of network addresses the app contacts** (for example "the media server in the home network; plex.tv for
   sign-in"), and every third-party library with its licence.
7. **Licence** – MIT or a licence compatible with it (for example BSD-2-Clause, BSD-3-Clause, ISC, Apache-2.0), with the
   copyright and licence notice of the reference kept where its code is used. By submitting you agree that the maintainer
   may build, sign and distribute the app under that licence.

Never put tokens, passwords, IP addresses of your home network, names or titles from your own library into the
submission, the repository or the screenshots. The maintainer will never ask you for credentials.

### How the maintainer reviews it

Before anything is offered here:

1. **Completeness and licence:** everything above is there; the licence fits; no "Plex" in the name or icon (policy
   above).
2. **Code review:** the maintainer reads the source – on the web route mostly the difference to the reference version
   it was built from. The app must contact nothing but the user's own media server and the services the spec allows
   (for example plex.tv for sign-in): no telemetry, analytics, ads, tracking, no code loaded from the internet at run time,
   no obfuscated or minified code without its source, no more permissions in the app manifest than it needs.
3. **Reproducible rebuild:** the maintainer builds the app from the reviewed tag in a clean environment with your
   instructions. Where the platform's packaging is deterministic, the checksum must match your build; otherwise the
   maintainer's own build is the one offered.
4. **Privacy scan:** `tools/privacy_scan.sh` over the source tree, and a look at every picture.
5. **Test on a real TV:** if the maintainer has access to a TV of that kind, he runs the smoke test (TEST-PLAN.md section
   2) with the rebuilt package → *maintainer-tested*. Otherwise the entry is marked *community-tested*, based on your
   results.
6. **Publish:** the rebuilt package goes into a release of this repository with its SHA-256 checksum in `SHA256SUMS`
   (signed with the maintainer's key where the platform requires a signature; if a signature only works on registered
   devices, the collection offers the source, the build instructions and your guide instead of a package). Your entry in
   `ports.json` gets `"collection": "maintainer-tested"` or `"community-tested"`.

**Updates** go through the same review (the maintainer looks at the changes since the last reviewed tag). An app in the
collection that is not updated for a newer spec is marked as built against an older spec, like every other port.

**Right to refuse and remove.** The maintainer may decline a submission, or remove an app from the collection at any
time – for example when a review finds a problem, a report comes in, or the app can no longer be maintained – without
having to give detailed reasons. Linked entries are not affected by that unless they break the policy above.
